# Project 6: EC2 + RDS Three-Tier Architecture

## What this is
A classic 3-tier application architecture on AWS. A web server (EC2) in the public subnet serves a Python Flask app, which connects securely to a managed PostgreSQL database (RDS) in a private data subnet. Credentials are managed by AWS Secrets Manager. Access to the EC2 instance is via AWS Systems Manager, with no SSH keys required.

## Why this matters in a real job
Every cloud engineering and security role assumes you know how to wire this up correctly. This project proves:
1. **Network isolation:** The database is unreachable from the internet. It only accepts traffic from the app server.
2. **Least privilege:** The app server can only read the specific database secret, nothing else.
3. **Secrets Management:** Passwords are not stored in code, user data, or environment variables in plaintext. They are retrieved dynamically at runtime.
4. **Managed Infrastructure:** We do not manage OS patches for the database; RDS handles it. We do not manage SSH keys; SSM handles it.

## Architecture
[ Internet ]
     |
[ Internet Gateway ]
     |
[ Public Subnet ] ---> [ EC2 (App Tier) + nginx + Flask ]
                               |
                               | (Port 5432)
                               v
[ Private App Subnet ] -> [ RDS PostgreSQL (Data Tier) ]
                               ^
                               | (Password)
                         [ Secrets Manager ]

## Design decisions and tradeoffs
| Decision | Alternative | Why we chose this |
|----------|-------------|-------------------|
| SSM Session Manager | SSH Bastion Host | No open port 22, no key management, full AWS CloudTrail audit log of every command. |
| Secrets Manager | Parameter Store / Env Vars | Secrets Manager supports native database rotation (30 days). Parameter Store is free but lacks rotation. Env vars are insecure. |
| Flask + Python | Node.js / PHP | Python aligns with previous projects (Lambda). Flask is minimal, requiring only a few lines. |
| db.t3.micro | db.m5.large | Free tier eligible (750 hours/month for 12 months). Fine for portfolio. |
| Single-AZ | Multi-AZ | Single-AZ is free tier. Multi-AZ doubles cost. We document this for production. |
| Public EC2 | Private EC2 + ALB | An ALB costs $18/month. A public EC2 with strict security groups is acceptable for a lab. |

## Security posture
- **Database:** Private subnet only. Security group `db-sg` only allows port 5432 from `app-sg`.
- **Web Server:** Public subnet. Security group `app-sg` only allows port 80 (HTTP) from 0.0.0.0/0, and port 22 is CLOSED. SSM is used for admin access.
- **IAM:** EC2 role can only `secretsmanager:GetSecretValue` on this specific secret, and use SSM.
- **Secrets:** PostgreSQL password is generated by Terraform, stored in Secrets Manager. It is never printed to the console.

## Common failure modes
- **EC2 cannot reach RDS:** Check route tables (must have a path, even if just local to the VPC) and security groups.
- **Flask 500 error:** Check the EC2 CloudWatch logs. Usually a DB connection issue or missing `psycopg2` library.
- **Secret Access Denied:** The IAM role attached to EC2 is missing the policy or the secret ARN is wrong.

| Symptom | Cause | Fix |
|---------|-------|-----|
| App returns `$DB_HOST` error | `user_data` script changed, but EC2 wasn't rebooted | Run `terraform apply -replace="aws_instance.app_server"` |
| App returns 502 Bad Gateway | `user_data` script still installing packages | Wait 3-4 minutes after apply completes |
